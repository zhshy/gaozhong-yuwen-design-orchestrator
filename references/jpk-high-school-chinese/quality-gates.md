# 门禁 JPK-01～JPK-10

> 第 8 步的判定依据。**本文件是 JPK 门禁的唯一定义处**，`SKILL.md` 只记一条指引，不复述判据。
> 红线 17–26 的展开理由也放在这里。

---

## 1. 卡片式总览

| 门禁 | 名称 | 判据 | 最高分档 |
|:-:|---|---|:-:|
| JPK-01 | **节点门禁** | 节点存在 ＋ 标题全等 ＋ 学科／年级／教材匹配 | **BLOCK** |
| JPK-02 | **依据门禁** | 能回溯 节点→教材→单元→课标→目标；节点是 A、依据是 B | **BLOCK** |
| JPK-03 | **目标门禁** | 每条目标有行为动词 ＋ 教学点 ＋ 学习证据 ＋ 评价 | **BLOCK** |

## 2. 逐道判据

### JPK-01 节点门禁

**查**：`node_exists` / `title_exact_match` / `subject_match` / `grade_match` / `textbook_match` 五项布尔。

**BLOCK 情形**：任一项非 `true`，或任一项为 `unknown`。

**判据来源**：`catalog-node.md` §3、§5。**本模式唯一不做降级的一处**——拿不到证据即停，不许"推定通过"。

---

### JPK-02 依据门禁

**查**：能否从目标往回走通七跳（节点→教材→单元→任务群→水平→素养→目标），每一跳说得出上一跳。

**BLOCK 情形**：
- 任一跳说不出 → 断链
- **节点是 A、依据是 B**（节点定《劝学》，依据链却从别的单元的条目接上来）

**判据来源**：`alignment.md` §1、§2。

---

### JPK-03 目标门禁

**查**：每条目标四个要件——行为动词 / 教学点 / 学习证据 / 评价。

**BLOCK 情形**：
- 缺任一要件
- 出现"提高审美情趣""培养人文情怀""增强文化自信"**单独作为目标**（无行为动词、无可检验证据）
- 目标条数 > 3

**注意**：维度放宽（`alignment.md` §5）**只放宽"是否分属三个维度"，不放宽本条的四个要件**。

---

### JPK-04 教学评一致门禁（最高优先级）

**查**：主链五节是否闭合。

```
OBJ → TP → ACT → EVID → AS
```

**BLOCK 情形**：缺任一节，或某节指向不明确（如"多个活动对应多个目标"但说不清哪个对哪个）。

**为什么是最高优先级**：这条不过，其余九道门禁的 PASS 都无意义——**材料齐全但逻辑不闭环，正是当前精品课最普遍的问题**。评审看的第一件事就是"这节课教的和评的是不是一回事"。

**判据来源**：`alignment.md` §3、§4、§6。

---

### JPK-05 任务单门禁

**查**五项：
1. 由目标产生（`objective_id` 非空）
2. 由活动产生（`teaching_point_id` 非空）
3. 要求学生**实际行动**（动作动词）
4. 产生**学习证据**（`evidence` 非空且具体）
5. 与**视频任务一致**（编号一一对应）

**BLOCK 情形**：任一不满足；或出现禁装项（答案／设计意图／教师活动等）。

**WARN 情形**：任务数 > 3 或任务数 ＝ 1。

**判据来源**：`task-sheet.md`。

---

### JPK-06 作业门禁

**查**（按优先级顺序）：
```
① 目标回指 → ② 课堂承接 → ③ 学习证据 → ④ 评价标准 → ⑤ 分层
```

**BLOCK 情形**：测了没教的东西（②不过）；无产出或无证据；`rubric` 是空洞评价词；题干含结论。

**WARN 情形**：某题回指不上目标 → **删题**。

**不扣分**：三档不齐（三档已是格式选项）。

**判据来源**：`homework.md`。

---

### JPK-07 技术适切门禁

**查**：五问是否逐问作答；`technology_value` 是否分档且与第 5 问一致。

**WARN 情形**：
- 用了技术但说不出解决什么教学问题
- 学生行为无变化（`low` 档）却把它当作"亮点"
- 第 5 问答"完全一样"却仍写进"信息技术融合"的论述

**BLOCK 情形**：
- 技术成为活动负担（操作时间 > 语文任务时间）
- AI 生成内容被当作学生的学习证据
- 出现"必须使用 AI／必须数字化／必须有 AI 助教"等表述

**判据来源**：`technology-fit.md`。

---

### JPK-08 课件门禁

**查**六项与母本一致：节点名 / 课题 / 任务顺序 / 主问题文字 / 文本引用 / 作业。

**BLOCK 情形**：
- 任务顺序与母本不一致
- 主问题文字**语义**漂移（为压字数改写导致指向改变）
- 课件出现教学目标、设计意图、作业答案、方向备注、教师适配调整（红线 11）

**WARN 情形**：为压字数删去虚词、语义未变 → 建议同步。

**不另建课件规范**：课件的生成标准仍在 `chinese-lesson-design` 的「配套 PPT 交付标准」，本模式**只加一层一致性门禁**。

**判据来源**：`material-consistency.md`。

---

### JPK-09 视频门禁

**查**：
- 视频核心任务 ＝ 教学设计核心任务 ＝ 任务单任务
- **`SEG 学生任务 ⊆ 课堂学生活动`**
- `SEG.student.action` 非空；纯讲授段连续 ≤ 2 段且合计 ≤ 全片 1/3
- 时间轴无断档；`visual` 非空

**BLOCK 情形**：
- **视频中出现课堂设计中不存在的新任务**（`JPK-VIDEO-001`）
- **视频里教师替学生说结论**，而教学设计说学生自己比较（`JPK-VIDEO-002`）
- 纯讲授段超标
- 段落挂不上目标（应删段）

**判据来源**：`micro-lesson-runtime.md`、`alignment.md` §6。

---

### JPK-10 完整件门禁（本模式下经一次改判）

**四件本技能产出并核验**：

```
① 教学设计 ✓   ② 学习任务单 ✓   ③ 课件 ✓   ④ 作业练习 ✓
```

缺一即 **BLOCK**。

**微课视频只核验一件事**：

```
⑤ 微课视频：运行稿存在 且 与教学设计一致
```

**成片不在核验范围。**

> **为什么必须这样改判**：本技能**不规定视频制作规范**（`2026-rules.md` §5），也就不产出、不处理成片。
> 若仍按"成片"核验，这道门禁会要求本技能**不提供的东西**——门禁就变成了摆设。
> 判据必须与产出边界对齐：**能产的才核，不能产的不核。**

**判据来源**：`2026-rules.md` §2、§5。

## 3. 分档语义

| 档 | 含义 | 动作 |
|:-:|---|---|
| **PASS** | 判据全部满足 | 继续 |
| **WARN** | 有可改进处，但不阻断 | **记录在交付报告里**，随附建议；不阻断提交 |
| **BLOCK** | 违反硬性判据 | **停止，修复后重跑该门禁**；不许"先提交再说" |

**两条纪律**：

1. **BLOCK 不许降级为 WARN**。`WARN` 是"够用但不完美"，`BLOCK` 是"错了"。把 BLOCK 写成 WARN，等于把错误藏起来。
2. **WARN 必须出现在交付报告里**。不许"内部标记一下就过"——用户有权知道哪里不够好。

## 4. 交付报告（机器可读）

```yaml
jpk_submission_report:
  node: PASS ; curriculum: PASS ; objectives: PASS ; alignment: PASS
  task_sheet: PASS ; homework: PASS ; ppt: PASS ; video: PASS
  technology_fit: WARN ; package: PASS
  final: PASS
```

**字段对应**：

| 字段 | 门禁 |
|---|---|
| `node` | JPK-01 |
| `curriculum` | JPK-02 |
| `objectives` | JPK-03 |
| `alignment` | JPK-04 |
| `task_sheet` | JPK-05 |
| `homework` | JPK-06 |
| `technology_fit` | JPK-07 |
| `ppt` | JPK-08 |
| `video` | JPK-09 |
| `package` | JPK-10 |
| `final` | 汇总 |

**`final` 的算法**：

```
任一 BLOCK  → final = BLOCK
无 BLOCK 但有 WARN → final = WARN
全 PASS  → final = PASS
```

**`final = PASS` 是 `SUBMISSION_FREEZE` 的前置条件**（`final = WARN` 允许冻，但须把 WARN 逐条列给用户并确认）。

## 5. 明确不做

**不输出分数预测。**

| 不做 | 为什么 |
|---|---|
| "预计 92 分" | 评审不是稳定算法，各地还有地方细化指标 |
| "一等奖概率 80%" | 同上；且会诱导用户按"分数"而非"教学"做决策 |
| "排名前 10%" | 无数据支撑 |

**本技能只回答三个问题**：

> 哪里**缺证据**？哪里**断链**？哪里有**形式主义**？

这三个问题都有明确判据（§2），也都可复核。分数没有。

## 6. 检查清单

- [ ] 十道门禁**逐道**给出结论（PASS／WARN／BLOCK），**没有"整体不错"这种总评**
- [ ] 每条 **WARN／BLOCK 都写清"哪一件、哪一处、差在哪"**
- [ ] **BLOCK 未被降级为 WARN**
- [ ] **所有 WARN 都进了交付报告**，且已逐条告知用户
- [ ] `final` 按 §4 算法得出
- [ ] `final` 非 PASS 时，已明确说明是否允许冻结及理由
- [ ] 交付报告**机器可读**（YAML 结构完整，无自由文本段落混入）
- [ ] **未输出任何分数或概率预测**
