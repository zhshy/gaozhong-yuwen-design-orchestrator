# 官方节点锁（第 0.5 步）

> **这是精品课与普通备课最本质的差别：节点先于教学设计。**
> 普通模式从"篇目"出发；精品课从"**平台上真实存在的那个目录节点**"出发。
>
> **执行第 0.5 步前先读完本文件。** 这一步**不允许凭印象做**。

---

## 1. 为什么必须放在设计之前

官方规定：学科课程类**原则上同一目录节点只推荐 1 节**。

这句话的含义是：

- 节点是**稀缺资源**，不是提交时才去填的一个字段；
- 一旦选错节点（名称不对、年级不对、教材版本不对），**后面全部工作都建立在一个不会被接受的选题上**；
- 而这时候教学设计、任务单、课件、作业都已经做完了——**返工成本最高、也最不该省**。

所以流程由 `第0步 → 第1步` 改为：

```
第0步 确认输入  →  第0.5步 官方节点锁  →  第1步 定依据  →  …
```

**未通过本步，禁止进入母本冻结。**（也能进第 1–6 步——那是"先探路"；但冻结前必须补上节点结论，否则整条链断在起点。）

## 2. `CatalogNode` 字段表

对用户呈现时用表格，**不给用户看 YAML**。每个字段都带状态标记，沿用四态（`confirmed` / `inferred` / `missing` / `needs_verification`）。

| 组 | 字段 | 说明 | 允许的状态 |
|---|---|---|---|
| 平台 | `platform.name` / `platform.year` | 报送平台名、年度 | `confirmed` |
| 学科定位 | `subject`＝语文 / `stage`＝高中 / `grade` | 年级须具体（如"高一"） | `confirmed` |
| 标题 | **`official_title`** | 平台节点**原文**，一字不改地抄 | `confirmed` |
| 标题 | **`submitted_title`** | 拟提交名 | `confirmed`；**须与 `official_title` 全等** |
| 教材 | `textbook.publisher` / `.edition` / `.volume` | 出版社／版次／册次 | `confirmed` 或 `needs_verification` |
| 节点标识 | `node_id` | 平台给的节点标识（若有） | `confirmed` |
| 取证 | `source.url` / `.checked_at` / `.evidence` | 来源、核对时间、截图或原文摘录 | `confirmed` |
| 核验 | `node_exists` / `title_exact_match` / `subject_match` / `grade_match` / `textbook_match` | **五项布尔** | 布尔 |
| 结论 | `status` | `PASS` / `WARN` / `BLOCK` | — |

**注意与普通模式第 0 步的关系**：`submission` 是**七组字段之外的第八组**，只在 `quality_course` 下必填；普通模式**不填、也不显示**这一组。

## 3. 检索与核验（五道）

```
① 节点存在  →  ② 学段＝高中  →  ③ 学科＝语文  →  ④ 教材版本对应  →  ⑤ 年级对应  →  ⑥ 标题全等
```

前五道决定"这个节点是不是你要的那一个"；第六道决定"你能不能交这一个"。

**逐道判据**：

| # | 判据 | 拿不到证据时 |
|:-:|---|---|
| ① | 平台目录里能查到该节点 | **BLOCK** |
| ② | `stage` ＝ 高中 | **BLOCK** |
| ③ | `subject` ＝ 语文 | **BLOCK** |
| ④ | 教材版本与节点标注一致，且**与学生实际用书一致** | **BLOCK**（可先记 `needs_verification`，补齐证据后复核） |
| ⑤ | 年级一致 | **BLOCK** |
| ⑥ | `official_title === submitted_title`，**字符串全等** | **BLOCK** |

---

## 4. 标题匹配：为什么"相似度 95%"不能用

**唯一允许的判定是字符串全等（含标点、空格、数字写法、书名号的有无）。**

| 用法 | 允许？ |
|---|:-:|
| 模糊匹配用于**检索**（"我大概记得叫《劝学》"→ 先搜出来有哪些节点） | ✅ 允许 |
| 模糊匹配用于**判定**（"95% 像，应该就是它"） | ❌ **禁止** |

**理由**：标题是提交口径本身。差一个字，就是另一个节点。而平台节点的差异往往正是**看起来最无关紧要的那一处**——

```
《劝学》          vs  《劝学（节选）》
《赤壁赋》        vs  《前赤壁赋》
必修上册第X单元   vs  必修上册 X.XX
```

"相似度"高，恰恰说明它**可能是另一个节点**。用相似度判定，等于把"没核对"包装成"核对过了"。

**发现不一致时怎么办**：**不要改节点名去迁就你的设计**，也不要改设计去迁就一个含糊的记忆——
把两个名字**并列摆给用户**，请他从平台页面直接复制节点原文。这是唯一可靠的做法。

## 5. 失败即 BLOCK，且**不降级**（本模式唯一一处）

| 情形 | 结果 |
|---|---|
| 官方节点不存在 | **BLOCK** |
| 标题不完全一致 | **BLOCK** |
| 学科不是高中语文 | **BLOCK** |
| 年级不一致 | **BLOCK** |
| 教材版本无法确认 | **BLOCK**（可先 `needs_verification`，补齐证据再复核） |

### 降级边界（重要，不要跳过）

本技能**没有**智慧平台的查询接口。节点核验只有两条路：

1. **用户提供**平台截图／页面原文；
2. 本技能**联网检索**后，**标注来源 URL 与核验时间**。

> **两条路都拿不到证据时，不得降级为"推定通过"。**
> 按"核心正确性无法保障"处理：**停止流程，说明原因**，请用户补证据。

**为什么这一处不让步**：其余各步都可以按证据强度分档（PASS／WARN／`needs_verification` 先往下走），因为它们在流程内部可以被修正；而**节点是流程的输入**——输入错了，后面每一步都会忠实地把错误放大。

**交付话术**：

> "节点这一项我查不到可靠依据，**不能替你推定**。请你从国家中小学智慧教育平台的目录页把节点名称**原文复制**给我（截图也行），我核对完再往下做。这一步做错，后面四件材料都要重做。"

## 6. 取证与保存

**核对完必须留痕**，否则下次还是"凭印象"。

| 存什么 | 要求 |
|---|---|
| `source.url` | 核对所用页面的 URL |
| `source.checked_at` | 核对时间（`YYYY-MM-DD`）——平台节点**会调整**，这决定了这个结论的保质期 |
| `source.evidence` | 截图文件路径，或**节点原文的逐字摘录** |
| 五项布尔 | 逐项写清 `true` / `false` / `unknown`，**不许只写一个总的"通过"** |

**落点**：示例里对应 `examples/劝学/quality-course/01-catalog-node.md`；正式交付时并入教学设计的「依据」节，并作为最终交付报告 `jpk_submission_report.node` 的取值来源。

## 7. 常见违规

| 违规 | 表象 | 为什么错 |
|---|---|---|
| **相似度判定** | "名称基本相同，应可通过" | 标题是提交口径，差一个字就是另一个节点（§4） |
| **事后补节点** | 设计全做完才去查节点，发现名字不符 | 节点必须在选题层锁定（§1） |
| **拿记忆当证据** | 凭以往印象写节点名，无 URL、无时间、无截图 | 平台节点会调整，无时间戳的结论不可用（§6） |
| **只写总判** | 五项布尔合成一个"通过" | 无法定位是哪一道没过（§6） |
| **教材版本含糊** | 只写"统编版"，不写版次册次 | 官方要求依据**教育部审定教材**，版次册次是核对口径（§3 ④） |
| **降级通过** | 拿不到证据，写成"推定通过" | 本模式唯一禁止降级的一处（§5） |

## 8. 检查清单（第 0.5 步收尾逐条打勾）

- [ ] `official_title` 是**从平台原文复制**的，不是我凭记忆写的
- [ ] `official_title === submitted_title` **字符串全等**（连标点、空格、括号、数字写法都比过）
- [ ] 五项布尔**逐项**写了 `true`／`false`／`unknown`，没有合成一个"通过"
- [ ] `textbook` 记到**出版社／版次／册次**，且与学生实际用书核对过
- [ ] `source` 三件齐全：URL ＋ 核对时间 ＋ 截图或原文摘录
- [ ] `status` 有明确结论（`PASS` / `WARN` / `BLOCK`）
- [ ] 若为 `BLOCK`：**已停止流程并说明原因**，没有"先做着看"
- [ ] 若证据拿不到：**已明确告知无法推进**，没有推定通过
