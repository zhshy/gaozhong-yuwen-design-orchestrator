# 课情卡（第 0 步产出）

本文件是 `SKILL.md` **第 0 步**的细则，也是**红线 7「不编造原文和课时数」的落地形态**。

一句话：**把这次备课的全部输入参数收进一张卡，每个字段标出"它靠不靠得住"。**

---

## 一、为什么要有这张卡

旧写法只有一句话兜着：「拿不准的原文、课时数一律标注"待核对"」。

一句话的约束有三个漏洞：

1. **只点名了两类**（原文、课时数）——教材版本年份、学情来源、班级规模同样可能编造，却没人管；
2. **"拿不准"由谁定义**——模型自己觉得"差不多知道"，就不标了；
3. **标了容易掉**——交付前一美化，"待核对"三个字常被当成碍眼的东西删掉。

课情卡把这一句变成**逐字段的状态标记**：卡上没有裸字段，任何一个值都必须回答"你凭什么这么写"。漏洞 1 由字段表覆盖，漏洞 2 由判定决策树覆盖，漏洞 3 由「必须冒泡」规则覆盖。

---

## 二、字段表（路由字段 ＋ 七组 ＋ 精品课第八组）

内部用 YAML 承载（便于下游按字段取值），**对用户呈现时一律换成第三节的表格**——不给用户看 YAML。

```yaml
交付模式:        # ★ 路由字段：普通备课（默认）/ 精品课
                      #   决定走七步还是九步，第 0 步必须定下来
                      #   注意：这不是 课型.模式（讲读/自读/活动），两者互不相干
课文:
  题名:            # 篇目名，如《劝学》
  作者:
  原文:             # 课文原文的核对状态（用书印次 / 字形 / 篇目修订）——原文类字段只能 已确认 或 待核验
  文体:            # 文体，如说理散文 / 近体诗 / 新闻通讯
  教材:         # 教材版本，如 统编版
  年级:            # 必修 / 选择性必修
  学期:         # 上册 / 下册
  单元:             # 单元，如 第六单元
课型:
  类别:         # 单篇精读 / 单元整体 / 群文阅读 / 复习课 / 作文讲评
  模式:             # 讲读 / 自读 / 活动（≠ 交付模式）
  子类:          # 具体课型名（可选）
时长:
  课时数:         # 课时数
  单课时长:  # 每课时分钟数（默认 45）
学生:
  学校层次:     # 重点校 / 普通校 / 薄弱校（必问）
  班级人数:       # 班级人数
  已有基础:  # 已学相关内容
  已知:            # 学生大概已会的（第 3 步"备两头"用）
  难点:     # 学生大概卡住的（第 3 步"备两头"用）
教师:
  偏好风格:  # 教师偏好的课堂风格（可缺省）
教学情境:
  用途:          # 常规课 / 公开课 / 比赛 / 教研展示
  高考导向: # 是否指向特定考试与题型
  公开课:       # 是否公开课（影响呈现方式）
约束:
  作业时长: # 作业时长上限
  多媒体:       # 多媒体条件（有无投影 / 能否放视频）
提交:         # ★ 第八组：仅 交付模式 = 精品课 时必填
  年度:             # 年度，如 2026
  类别:         # 类别（本技能只做"学科课程类"）
  学段:            # 学段＝高中
  学科:          # 学科＝语文
  平台:         # 报送平台
  官方节点名:   # ★ 平台节点原文，必须逐字复制，不许凭记忆写
  教材版本: # 出版社 / 版次 / 册次
```

> ⚠️ **第八组 `提交` 不是"顺手多加的一栏"**，而是精品课模式的**输入前提**。
> 它填完**不等于节点就锁定了**——第 0.5 步还要按五道核验逐项判定，见 [`jpk-high-school-chinese/catalog-node.md`](jpk-high-school-chinese/catalog-node.md)。
> 普通模式（`普通备课`）下这一组**整体不存在**：不要因为"反正用不上"就先填上，**填了就进了母本**，会污染普通备课的交付物。

**必问四项**：`课文.题名`（或 `单元`）、`课型.类别`、`时长.课时数`、`学生.学校层次`。

**可缺省**：`教师.偏好风格`、`约束.*`、`课型.模式` / `子类`、`学生.班级人数`。

**`交付模式` 不属"可缺省"**——它必须是显式结论（从请求判断，判不准就问用户），因为整条流程的长度由它决定。

**高发风险字段**（这三处最容易出编造，标记时格外留神）：

| 字段 | 为什么危险 |
|---|---|
| `课文.原文` | **原文**（用书印次、异体字形、篇目修订）——最难自查、后果最重的一类；拿不准一律 `待核验`，并在母本与四份 Word 里保留"待核对"（《劝学》示例的两处即此类） |
| `课文.教材` / `年级` / `学期` | 用户常只说篇目，版本靠"默认"顶替——默认值必须标 `推断` 并写出依据 |
| `时长.课时数` / `单课时长` | 课时数直接决定课表与台阶分配，编一个数会让整份母本从头错到尾 |
| `学生.已有基础` / `已知` / `难点` | 学情最容易被"想当然"——没有依据的学情描述是第 3 步"备两头"的定时炸弹 |

## 三、四态判定决策树

对**每一个字段**依次问下去，走到第一个"是"就停：

```
① 用户明确说了这个值？
   └─ 是 → 已确认（直接用）
   └─ 否 ↓
② 这个字段涉及 原文文字 / 课时数 / 教材版本年份 三类之一吗？
   └─ 是 → 我方对它"记得但拿不准" → 待核验
           我方对它完全没有值     → 未提供（去问用户）
           注意：这三类**禁止 推断**（见下方红框）
   └─ 否 ↓
③ 能从用户已给的信息唯一推出吗？（如"公开课"→有旁听教师；"统编版"→版本体系）
   └─ 能 → 推断（必须写明依据）
   └─ 不能 ↓
④ 我方记得但拿不准吗？
   └─ 是 → 待核验
   └─ 否 → 未提供
```

> **红框规则（本文件最要紧的一条）**
> **凡涉及「原文文字」「课时数」「教材版本年份」的字段，只允许 `已确认` 或 `待核验`／`未提供`，不许标 `推断`。**
> 理由：这三类一旦推定错，错误会渗透到母本、四份 Word 与课件的每一页；而它们的正确来源是"用户说的"或"查得到的原文"，不是推理。宁可标 `待核验` 让用户花十秒确认，也不许用推定值充数。

四态速记：

| 状态 | 一句话 | 对外归入哪个栏目 |
|---|---|---|
| `已确认` | 用户说的 | ——（无需提示） |
| `推断` | 我推的（附依据） | 「**请核**」 |
| `未提供` | 没有值 | 「**缺失项**」 |
| `待核验` | 有值但不敢担保 | 「**待核对**」 |

## 四、对用户呈现的表格模板

第 0 步收尾、以及每次交付的开场，都按这个格式给。**"说明"栏对 `已确认` 写「—」，其余三类必写理由。**

```markdown
### 课情卡

| 字段 | 值 | 状态 | 说明 |
|---|---|---|---|
| 篇目 | 《劝学》 | `已确认` | — |
| 作者 | 荀子 | `已确认` | — |
| 文体 | 说理散文 | `推断` | 依必修上册第六单元选文属性推定 |
| 教材版本 | 统编版 | `推断` | 用户未说明；按本技能默认（统编版必修上/下册）推定 |
| 册次 / 单元 | 必修上册 · 第六单元 | `已确认` | — |
| 课型 | 单篇精读 | `已确认` | — |
| 课时数 | 3 课时 | `待核验` | 用户口述"三课时左右"，未确认是否含课后检测 |
| 每课时长 | 45 分钟 | `推断` | 按常规课时推定 |
| 学情层次 | 重点校 | `已确认` | — |
| 班级人数 | —— | `未提供` | 未提供，影响小组活动与朗读人次设计 |
| 学生已会 | —— | `未提供` | 未提供，第 3 步"备两头"缺一半 |
| 作业时长上限 | —— | `未提供` | 未提供，暂按 30 分钟设计 |
| 多媒体条件 | 有投影 | `推断` | 用户提到"要课件"，据以推定 |

**请核（推定值）**：文体、教材版本、每课时长、多媒体条件
**缺失项**：班级人数、学生已会、作业时长上限
**待核对**：课时数（3 课时是否含课后检测）
```

## 五、交付话术（三个栏目怎么落地）

- 「**请核**」（`推断`）：语气是"我按这个推进了，不对就说"。例：
  > 教材版本你没说，我按默认的**统编版必修上册**做；如果你用的是别的版本或册次，告诉我，我重出。
- 「**缺失项**」（`未提供`）：语气是"这一项我没有，先按某走，你给个准数我改"。例：
  > **学生已会**与**班级人数**这两项你没提。第 3 步定教学点要靠"学生疑难处"，所以这两项**会直接影响教学点**——能给尽量给；不给的话我会先按"普通校中等水平"作假设，并在母本里标出这是假设。
- 「**待核对**」（`待核验`）：语气是"这个数我不敢担保，请核实"。例：
  > **课时数**我按 3 课时排。若你实际是 2 课时（或 3 课时不含课后检测），课表第 5 节与台阶分配要重排，请先确认。

**三条纪律**：

1. **`未提供` 不等于可以用默认值**——用了默认值就必须标出来，并说明它是**假设**而非事实。
2. **`待核验` 字样在交付物里不许撤**——母本、四份 Word、课件对应位置保留"待核对"；用户确认后再由用户要求撤下，不许自己决定。
3. **不许把 `待核验` 悄悄降级成 `推断` 或 `已确认`**——三态的严厉程度是 `已确认` ＞ `待核验` ＞ `推断`（就"敢不敢用"而言），降级即编造。

## 六、与下游的对接点

| 下游 | 用哪些字段 | 怎么用 |
|---|---|---|
| 第 3 步备两头 | `学生.已知` / `学生.难点` | 直接作为"学生疑难处"的一半；若为 `未提供`，须在母本里注明教学点是基于假设定的 |
| 第 5 步母本 | **全卡** | 母本开头回显本卡（含四态），`未提供` 与 `待核验` 单列成「待核对事项」一段，置于正文之前 |
| 第 5 步附二 | `教材` / `年级` / `学期` | 教材与课标版本核对说明的核对对象 |
| 第 7.1 步四份 Word 页眉 | `题名` / `课型.类别` / `时长.课时数` / `学生.学校层次` | 页眉字段一律取自本卡，不许各自另填 |
| 第 7 步一致性自检 | `题名` / `时长.*` | 四份文档的篇目名、课时数据逐字比对，**以本卡为准**；对不上就改文档，不改卡 |
| 第 7.2 步课件 | `约束.多媒体` / `教学情境.公开课` | 决定配图取舍与页数尺度 |

## 七、反例：六种最常见的违规

1. **静默填充**——用户只说"帮我备《劝学》"，就把课时写成 3 课时、学情写成"普通校"，一个状态标记都没有。
2. **推定当事实**——`教材` 是推定的，却在页眉里写得斩钉截铁，也不注明依据。
3. **"待核对"被美容掉**——交付前嫌"待核对"三个字碍眼，把它删了。这是本流程最严重的一类违规，直接踩红线 7。
4. **缺失项用默认值顶替**——班级人数没给就按 45 人写，不标 `未提供`，读者无从知道这是假设。
5. **拿 `待核验` 逃避提问**——本是 `未提供`（完全没值），却标成 `待核验`，省掉"问用户"这个动作。
6. **状态自相矛盾**——标 `已确认`，但说明栏写的是"按其属性推定"。

## 八、第 0 步检查清单

- [ ] **`交付模式` 是否已显式定下**（`普通备课` / `精品课`），且**没有混用** `课型.模式`
- [ ] 七组字段是否都已列出（缺省项也注明"可缺省"，不是不列）
- [ ] **若 `交付模式 = 精品课`**：第八组 `提交` 是否七个字段都填了，`官方节点名` 是否是**平台原文逐字复制**的
- [ ] **若 `交付模式 = 普通备课`**：第八组是否**整体未填**（填了就是污染）
- [ ] 每个字段是否都带四态标记之一（**无裸字段**）
- [ ] 每个 `推断` 是否写了推定依据
- [ ] `课文.教材` / `时长.课时数` 两类高风险字段是否严格未用 `推断`
- [ ] `未提供` 项是否已向用户提问；未问到的是否列进「缺失项」并说明所用假设
- [ ] `待核验` 项是否已列入「待核对」，且承诺在交付物中保留字样
- [ ] 必问四项（篇目/单元、课型、课时数、学情层次）是否都拿到了值或都已标状态

## 九、来源与依据

- **提出背景**：2026-09-17 的一次技能审查指出，红线 7 当时只由"拿不准就标待核对"一句话承载，缺少可执行的判定规则，实际执行中极易滑过（《V2 架构可行性评估》把它列为性价比最高的 P0 改进项）。
- **与本技能既有条款的关系**：本卡不新增红线，而是**把红线 7 具体化**——红线条数不变（仍为 16 条），第 7 条的判定标准改为本文件的决策树。
- **为什么不放进 `chinese-lesson-design`**：课情卡是**流程入口的输入规范**，服务的是七步编排本身（四个下游对接点全部在本技能内），不是交付格式。交付格式权威管的是"文档长什么样"，不管"输入参数怎么标状态"。故此项留在本技能。
- **可信度**：字段清单属**设计取值**（本技能自定，非引自权威文献）；但"原文/课时数/版本年份三类禁止推定"这条硬规则，直接来自红线 7 的立法意图，属**甲级**（本技能自身的强制条款）。
