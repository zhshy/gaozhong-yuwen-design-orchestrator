# 课件生成通道：ppt-master

> 本文件规定"课件 `.pptx` 由 `ppt-master` 生成"这一通道怎么用。**版式规范不在这里**——七条硬标准、页数分配、单页规则、配图规范仍在 `chinese-lesson-design` 的「配套 PPT 交付标准」，本文件只管**接得上、不跑偏、出了事怎么收**。

---

## 0. 这条通道是什么

| 项 | 内容 |
|---|---|
| 上游 | `hugohe3/ppt-master`（MIT，当前 v6.7.3） |
| 工艺 | 逐页手写 SVG → 编译为 DrawingML → 封装 `.pptx` |
| 产物特征 | **原生可编辑**：形状、文本框、连接线都是独立对象，不是整页贴图 |
| 不吃什么 | 不吃固定模板；版式由它按内容现场设计 |
| 本技能的控制点 | 喂什么、走哪条 profile、确认门在哪、出来的东西怎么落盘 |

**定位**：**唯一通道**。课件一律由它生成，**不设第二个通道**——不以"快""临时""能看就行"为由改走 `workbuddy-pptx`（旧名 `tencent-pptx`）。

**为什么不设回退**（理由要留住，免得以后又被"快一点"说动）：两条通道＝两套版式、两套质量下限，交付就不稳定；而模板填充式通道做不到 §3.1 的源头控制——课件版红线要靠人逐页挑刺，那正是本技能要避免的。**通道只有一个，标准才只有一个。**

> 唯一的松动是**故障**：`ppt-master` 真的修不好时，代理**停下报告**，是否换通道由**用户当场决定**（见 §8）。代理不得自作主张降级。

## 1. 三条硬规矩（先看这个，再谈步骤）

| # | 规矩 | 为什么 |
|:-:|---|---|
| 一 | **一律走 Default 路线**（`workflows/generate-pptx.md`），**禁止 Quick**（`profiles/quick-generate.md`） | Quick 明确"decide without interaction、omit Confirm UI、spec/lock 全略"——**跳过确认门**，与本技能 7.2「两阶段，不许跳过确认」直接冲突。唯一例外：用户**明说**"直接出、不用给我确认" |
| 二 | **禁止 Beautify / Image-to-PPTX 两条 profile** | Beautify 的前提是"已有 pptx 要保持原设计 1:1"，Image-to-PPTX 的前提是"有整页图片要还原"。课件是从母本**新造**，两者前提都不成立 |
| 三 | **已有 `.pptx` 只改文字 → 走 Edit Native PPTX**（`workflows/edit-native-pptx.md`） | 这一条接替了原来 `workbuddy-local-office-edit` 的"改内容"职责；不允许为了改两个字重新生成整份 |

## 2. 准入条件（三条，缺一条就不做）

1. **母本已冻结**（第 6 步检查点全过）。母本没冻结就生成 PPT ＝ 返工两次。
2. **课件源稿已派生**（见 §3）。**这一步不许省**。
3. **`ppt-master` 可用**：`attribution_guard.py` 返回 0（见 §9）。

---

## 3. 课件源稿：这条通道最容易翻车的地方

### 3.1 为什么必须先派生源稿

`ppt-master` 把**喂进去的源材料当作"内容"**来读——它不理解"这是教师自用、不投给学生"。**把冻结母本整份丢进去，教学目标、设计意图、预设应对、作业答案会被它当正文排进页面。**

课件版红线（不出现教学目标、设计意图、预设应对、教师自述、作业答案、方向备注、教师适配调整）**靠源头控制，不靠生成后删**。生成出来再逐页挑刺，一定漏。

### 3.2 源稿长什么样

从冻结母本派生出**一份** `课件源稿.md`，与母本同目录，只装投给学生的内容：

| 装 | 不装 |
|---|---|
| 课题名、作者与出处 | 教学目标（编号与文字都不进） |
| 朗读／感知的引导语 | 设计意图、预设与应对 |
| 任务页：任务名 ＋ 指令（≤ 120 字） | 教师活动流水账、"教师自述"式旁白 |
| 主问题页：主问题原文 ＋ 追问（≤ 30 字） | 方向备注、教师适配调整 |
| 原文页：课文原句（一屏放得下） | 作业答案、量规三档描写 |
| 小结页：四字短语式结论 | 检测题答案、评分细则 |

**标题一律写成「环节／任务／步骤 ＋ 四字短语」**，不写光秃秃的"作业""小结"——这条要在源稿里就写好，不要指望生成时自动补。

### 3.3 源稿与母本的关系

- 源稿是母本的**视图**，不是新稿：母本一改，源稿重出、PPT 重做（顺序铁律不变）。
- 源稿里的**主问题文字、任务顺序、板书层级**必须与母本逐字一致——这三项是 §7 一致性检查的对象，源稿阶段就对齐，后面才查得动。

## 4. 调用顺序：把人机确认门对齐

`ppt-master` 的 Default 路线有它自己的门（Stage 1 通信契约、Stage 2 方案）。**不要把这些门原样抛给用户，也不要问两轮。**

| 本技能 7.2 环节 | ppt-master 对应 | 谁确认 |
|---|---|---|
| 准入检查（§2 三条） | — | 本技能自检，不问用户 |
| 源稿 → Markdown | Step 1 `source_to_md.py` | — |
| 建项目、导入源 | Step 2 `project_manager.py init` / `import-sources` | — |
| 设计规格（画幅、页数、页面节奏） | Step 3 候选 ＋ Step 4 Strategist | — |
| **「页—内容」清单** | Step 5 Stage 2 方案 ＋ 页清单 | **用户（唯一一次确认门）** |
| 逐页出图 → 导出 | Step 6 SVG 编写 → Step 7 导出 | — |

**唯一的用户确认门**：把 Stage 1／Stage 2 的门合并成**一次**给用户，并且**翻译成本技能的话**——不要给用户看 `design_spec.md`，给他 §4.1 那张表。

### 4.1 交给用户的页清单格式（一页一行）

```
| 页码 | 标题（环节／任务 ＋ 四字短语） | 要点（正文原样） | 配图位 |
|:--:|---|---|---|
| 1 | 课题页 | 《劝学》· 荀子 | — |
| 2 | 初读正音 · 字音三辨 | …… | — |
```

- **要点一栏写正文原样**，不写"介绍作者"这种概述——用户看概述看不出这页能不能投。
- 同时报三个数：**总页数 / 最长页正文字数 / 计划配图张数**，让用户一眼判断是否越线。

## 5. 硬线必须写进规格与页清单

`ppt-master` 不知道语文课件的页数规矩。**下列约束不写进 `design_spec` 与页清单，它一定超**：

| 约束 | 值 | 写在哪 |
|---|---|---|
| 每课时页数 | 16–24；联读／整本书／长文 ≤ 40 | Stage 1 画幅与页数区间 ＋ 页清单总数 |
| 主问题页、环节／任务过渡页 | 正文 ≤ 30 字 | 页清单「要点」栏逐行核 |
| 任务页、结论页 | 正文 ≤ 120 字 | 同上 |
| 原文页 | 一屏放得下（超了拆页） | 同上 |
| 正文字号 | ≥ 18pt（目标 22pt） | `design_spec` 排版锁 |
| 标题格式 | 环节／任务／步骤 ＋ 四字短语 | 源稿即写好，页清单复核 |
| 配图 | 0–5 张，宁少勿多 | 页清单「配图位」 |

### 5.1 px ↔ pt 换算（写 SVG 时必须算对）

画布 1280×720 对应 13.33×7.5 英寸，**1pt ＝ 1.333px，即 SVG 里的 px 值 × 0.75 ＝ PowerPoint 的 pt 值**（导出后实测：`150px → 112.5pt`、`44px → 33pt`、`24px → 18pt`）。

| 硬线 | pt | SVG 里写 |
|---|---|---|
| 正文下限 | 18pt | **24px** |
| 正文目标 | 22pt | 29px |
| 常规正文 | 33pt | 44px |

**所以"正文 ≥ 18pt"在 SVG 里就是"font-size 不得小于 24"。** 别按 pt 直接写 px，会缩到 3/4。

**导出前逐页核字数**——这是唯一"生成完还能救"的检查；页数和字号越线只能回 Stage 2 改。

## 6. 配图：走宿主图像生成工具

| 项 | 规定 |
|---|---|
| 主路径 | **本机图像生成工具**，按母本的景物描写做影像蒸馏（与「配套 PPT 交付标准」的配图规范同口径） |
| 不用什么 | 图库检索（Openverse／Wikimedia）**不作主路径**——风格不统一，与课文意境对不上 |
| 判据 | **对得上文本哪一句或哪个史实**；对不上不放 |
| 数量 | 0–5 张；留白充足的页面才插图 |
| 归档 | 图落 `<篇目>/课件/assets/`，与母本同源；同类课复用，不重复入库 |

**禁止**：为了"填空位"生图。没有对得上的句子，宁可整页不配图。

## 7. 落盘与命名

| 环节 | 位置 |
|---|---|
| 生成工作区 | `<workspace>/courseware/<篇目>/`（ppt-master 的 project 目录，`svg_output/`、`exports/` 都在里面） |
| 交付件 | `<workspace>/output/<篇目>/<篇目>_课件.pptx` |
| 命名 | 不带书名号、不带空格、不带版本号（版本写页眉／备注） |
| 中间件 | `design_spec.md`、`页清单.md`、`svg_output/` 留在工作区，**不进交付目录** |

导出后**必须重命名迁移**——`exports/` 里那串时间戳文件名不是交付件名。

## 8. 故障处置（换通道须用户当场决定）

| 情形 | 处置 |
|---|---|
| `attribution_guard.py` 非零 | **停**，不检查、不修补、不绕过；如实告诉用户完整性校验没过 |
| 依赖缺失／脚本报错 | 按报错补依赖后**从 owning step 重跑**，不改设计 |
| 导出成功但页数／字数越线 | 回 Stage 2 改页清单（不是导出后删页） |
| 用了 Quick 才发现要确认 | 停，回 Default 补 Stage 1／2 的门 |
| 通道整体不可用（未安装、环境坏） | **先修**：按 §9 重新装／修环境，再从 owning step 重跑。**修不好 → 停下如实报告，把"是否换通道"交回用户决定**；代理**不得自行改用 `workbuddy-pptx`** |

**换通道不降标准**：若用户当场决定改用别的工具，用什么工具就按什么工具交付，但 §5 全部硬线与课件版红线**一条不减**。

**代理的默认动作是"修 + 报"，不是"绕"**：任何"为了赶进度先出了再说"的念头，都属于本条要禁止的自行降级。

## 9. 环境、命令与已踩的坑

| 项 | 值 |
|---|---|
| 技能目录 | `~/.workbuddy/skills/ppt-master/`（`SKILL_DIR` 即此路径） |
| Python 环境 | `~/.workbuddy/binaries/python/envs/ppt-master/bin/python`（隔离 venv，勿用系统 python） |
| 完整性门禁 | `<venv>/bin/python "${SKILL_DIR}/scripts/attribution_guard.py"`（实测 exit 0） |

**调用纪律**：`ppt-master` 要求把 `SKILL_DIR` 展开成绝对路径，**不许 `cd`、不许依赖当前工作目录**；每次工具调用都要展开一次。

### 9.1 出件是三段命令，不是一条

```bash
# ① 建项目（--format 只在画幅已被事实确定时给）
project_manager.py init <名称> --format ppt169 --dir <工作区>/courseware
# ② 补规格与执行锁，然后逐字段填实（[fill] 不许留）
project_manager.py scaffold-spec <项目>
project_manager.py scaffold-lock <项目>
# ③ 质量门禁 → 过了才允许导出
svg_quality_checker.py <项目> --canonical-authoring --stage final --json
svg_to_pptx.py <项目> -o <交付路径>
```

**没有 `spec_lock.md` 不让导出，没有通过的 quality report 也不让导出。** 这是它的设计，不是障碍——它把"跳规格直接凑页面"这条捷径堵掉了。

### 9.2 七个必踩的坑（均已实测）

| # | 现象 | 原因与处置 |
|:-:|---|---|
| 一 | `spec_lock.md is required` | 先 `scaffold-lock`，且 `[fill]` 必须填实；`typography` 的字号**只写数字**（`44`，不写 `44px`） |
| 二 | 字号报 `undeclared font-size 24 exceeds sparse limit` | 出现 ≥3 次的字号必须在 `spec_lock` 的 `## typography` 里立成角色锚点（如 `annotation: 24`）。**这是好事**：逼你把字号体系想清楚 |
| 三 | `page SVG is missing root data-pptx-page-role` | 每页根 `<svg>` 要给 `data-pptx-page-role`，取值只有 `cover` / `toc` / `section` / `content` / `ending` |
| 四 | 根级 `<g>` 报缺 `data-pptx-bounds` | 每个根级内容分组都要声明自己的子画布：`data-pptx-bounds="x y 宽 高"`。零散元素不分组也会报，先分组再给 bounds |
| 五 | 导出报 `PermissionError: EEXIST ... mkdir` | **本机宿主注入的 `sitecustomize.py` 把"目录已存在"当致命错误**（`exist_ok=True` 时反走 broker）。不改第三方源码：用包装脚本先把 `pathlib.Path.mkdir` 还原成原生实现，再调原导出脚本（见 §9.3） |
| 六 | 报 `<text> exceeds <g> data-pptx-bounds on the vertical axis … overflow 5%`（阈值也是 5%） | 分组声明的框装不下字。**页脚最常见**：`24px` 字的实际下沿比想象低，把页脚 bounds 放宽到 `64 650 1152 66` 即可；别去缩字号 |
| 七 | 质量门禁全过，但**文本框互相重叠**（视觉上不撞） | 大字号的行高 padding 会把文本框撑高。封面 96px 标题与正文行的**基线**隔 62px 时视觉没问题、**框**却重叠 49%。处置：把下方文字整体下压 16–20px，再用几何检查复核 |

**门禁查不到"重叠"**，所以要自己补一遍几何检查：遍历 pptx 所有文本框，查（1）是否越出画布（2）两框交叠是否超过小框面积的 25%。本项目 16 页实测 0 处。

### 9.3 导出包装脚本（绕开上述 shim 问题）

```python
import pathlib, runpy, sys
try:
    import sitecustomize as _sc
    if hasattr(_sc, "_orig_path_mkdir"):
        pathlib.Path.mkdir = _sc._orig_path_mkdir
except Exception:
    pass
sys.argv = ["svg_to_pptx.py"] + sys.argv[1:]
runpy.run_path("${SKILL_DIR}/scripts/svg_to_pptx.py", run_name="__main__")
```

用法：`<venv>/bin/python run_export.py <项目路径> -o <交付路径>`。**只在导出这一步用它**，其余脚本走原命令。

### 9.4 装了什么、没装什么

- **已装**：python-pptx、skia-pathops、uharfbuzz、Pillow、numpy、XlsxWriter、PyYAML、flask、edge-tts、mammoth、nbconvert、google-genai 等。
- **未装 `PyMuPDF`**：PDF → Markdown 那一路不可用，且它是 AGPL。**语文课件的源是 docx／md，用不到**；若某天要拿 PDF 当源，再单独装并复核许可。
- **字体**：导出走 PowerPoint 主题字体，`font-portability` 检查实测 passed。正文用宋体，标注用黑体系（`PingFang SC`／`Microsoft YaHei`）。

## 10. 检查清单（7.2 出件前逐条过）

- [ ] 母本已冻结，源稿是它的视图（不是另写的稿）
- [ ] 课件源稿里**没有**教学目标、设计意图、预设应对、教师自述、作业答案、方向备注、教师适配调整
- [ ] 源稿的主问题文字、任务顺序、板书层级与母本逐字一致
- [ ] 走的是 Default，没碰 Quick / Beautify / Image-to-PPTX
- [ ] 页清单已交用户确认，且用户看到的是"一页一行 ＋ 三个数"，不是 `design_spec`
- [ ] 每课时页数在区间内（16–24；长文 ≤ 40）
- [ ] 逐页正文字数在页型上限内；字号 ≥ 18pt
- [ ] 配图 ≤ 5 张，且每张对得上文本某一句
- [ ] 交付件已重命名迁到 `output/<篇目>/<篇目>_课件.pptx`
- [ ] 未因"快／临时"自行改用旧通道；若换过，是用户当场决定的，且交付说明已写明
