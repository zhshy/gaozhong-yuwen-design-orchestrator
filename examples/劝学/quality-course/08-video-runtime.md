# 08 微课运行稿（提交件 ⑤）

> **本技能产出运行稿，不产出成片。**
> **不规定**视频时长参数、分辨率、码率、片头片尾、字幕、体积、命名、上传限制——这些属"制作规范"，见 `2026-rules.md` §5。
> **不生成 `.mp4`。**

---

## 一、先解决那个矛盾：课堂时间表 vs 微课时间表

**两者并存，互为约束。**

| | 教学设计（提交件 ①） | 本运行稿（提交件 ⑤） |
|---|---|---|
| 按什么时长设计 | **完整一节课**（3 课时 / 135 分钟） | **微课时长** |
| 时间表 | **七列时间项**，Σ ＝ 135 分钟 | **SEG 时间轴** |
| 为什么 | "教学设计"本身是提交件，且官方要求"突出课堂实效"——**压成三段的课撑不起这一项** | 微课是独立呈现形式，有自己的节奏 |

**微课时间轴不是把课堂环节除以 3。**

```
❌ 错误做法：课堂 45 分钟 → 微课 15 分钟 → "每个环节 × 1/3"
✅ 正确做法：按微课的六拍节奏重排（§三）——只保留核心问题、核心任务、核心证据、迁移出口，其余舍去
```

**硬约束（红线 21 / JPK-09）**：

```
SEG 中的学生任务集合  ⊆  课堂设计的学生活动集合
```

- 视频里出现的每一个学生任务，**必须**在课堂设计里已经存在（编号对应）。
- **视频里冒出课堂设计中不存在的新任务 → BLOCK。**
- **反向不算违规**：课堂里有、视频里没有的学生活动，正常。本例课堂有 4 个活动（`ACT-01…04`），微课只呈现其中 3 个 ＋ 收束作答。

> **`duration` 的取值口径**：本技能**不规定**时长，由用户或本地通知给定。
> **本例未提供本地通知**，故 `duration` 三项标 **`needs_verification`**；下面 SEG 时间轴按 **12 分钟**排布，**仅用于演示节奏结构**，录制前须以通知正文与用户要求核对并重排。

## 二、`video_runtime`

```yaml
video_runtime:
  duration:
    target: "12:00"        # 演示值，needs_verification
    min: null              # 待通知给定
    max: null              # 待通知给定
  segments: [SEG-01 ... SEG-07]   # 见 §三
```

**结构字段（逐段）**：`id` / `time` / `objective_id` / `teaching_point_id` / `teacher` / `student` / `visual` / `technology` / `evidence`。

| 字段 | 内容 |
|---|---|

| `teaching_point_id` | `TP-01` |

| `teacher.script` | 「先只看这一句。他说的当然是靛青——可这是《劝学》，是谈学习的。他为什么拿靛青开头？」 |

### `SEG-02`｜关键阅读／关键证据　`01:10–03:20`（130 秒）

| 字段 | 内容 |
|---|---|
| `objective_id` | `OBJ-02` |
| `teaching_point_id` | `TP-01` |
| `teacher.action` | 逐处出示青、冰、木、金，请学生自己指出各自"变成了什么" |
| `teacher.script` | 「一处一处来。靛青是从蓼蓝里取的——变了吗？冰是水做的——变了吗？木头呢？」 |
| `student.action` | **圈画并填「物象—变化」表；并在「青，取之于蓝，而青于蓝」一句下圈出两处「于」，各写一个词注义** |
| `student.expected_output` | 表内两列填写 ＋ 两处圈画与旁注 |
| `visual` | 全屏 **P6**（物象页）→ 切 **P7**（"它们都指向一个字：变"） |
| `technology` | `enabled: false` |
| `evidence` | 「物象—变化」表 ＋ 圈画痕迹（即 `E-01`） |

> **P7 的顺序纪律**：`P7` 必须在学生自己归纳出"变"**之后**才出。顺序反了，这一页就从"印证"变成了"告知"。

| 拍 | 段 | 是否落实 |
|:-:|---|:-:|
| 1 问题建立 | `SEG-01` | ✅ 用"他为什么拿靛青开头"，不是"今天我们来学习…" |
| 2 关键阅读／关键证据 | `SEG-02` | ✅ 前 1 分 10 秒内已进入文本 |
| 3 学习任务 | `SEG-02`／`SEG-04`／`SEG-06` | ✅ 三个任务，每个都有学生动作 |

**四件"砍掉"清单的执行记录**（相对完整课堂）：

| 砍掉 | 内容 | 课堂上是否仍做 |
|:-:|---|:-:|
| 第 1 件 | 过渡语与寒暄 | — |

## 六、产出边界（本次明确）

**本模式产出**：运行稿（分镜表）／时间轴（SEG 序列）／画面设计（PPT 页次、板书、全屏与教师窗口关系）／教师语言（可直接照读）／学生任务（动作与产出）。

**本模式不产出、不规定**：

| 不做 | 理由 |
|---|---|
| 视频时长与格式参数 | 属制作规范 |
| 分辨率／码率 | 同上 |
| 片头片尾模板 | 同上 |
| 字幕规范 | 同上 |
| 文件体积与命名 | 同上 |
| 上传限制 | 同上 |
| **生成 MP4** | **本技能不声称生成视频文件** |

**交付话术（照此说）**：

> "我出的是**运行稿**——每一段讲什么、学生做什么、画面是什么、教师说什么，都写到位了。**录制、剪辑、成片参数**这些不在这份运行稿里，请交给录制环节。"

## 七、逐段技术核查

**全片 7 段，`technology.enabled` 均为 `false`**——本微课**不使用任何技术手段**（除画面本身）。

**为什么**：按 `technology-fit.md` 第 5 问，本课的教学难点（学生停在修辞层）**靠逐处圈画与填表即可解决**，技术不带来不可替代的行为变化。技术适切的结论已记为 `technology_value = helpful`（仅指课件投影），**微课段内不需要额外技术**。

> **这不是"技术不足"，是判断。** 本技能**禁止**出现"精品课必须使用 AI／必须数字化"的要求。
